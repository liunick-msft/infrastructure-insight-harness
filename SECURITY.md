# Security Policy

## Supported Versions

No production-supported release exists yet. Security fixes are applied to the current development branch.

## Reporting a Vulnerability

Use the repository host's private vulnerability reporting feature when it is available. Do not place credentials, device output, internal addresses, exploit details, or other sensitive evidence in a public issue.

If private reporting is unavailable, open a minimal public issue requesting a private contact channel without including vulnerability details. Maintainer contact information will be added before public release; no address is invented here.

## Security Boundary

The project is permanently read-only and catalog-authorized. Reports involving arbitrary command execution, policy bypass, host-key bypass, credential disclosure, redaction failure, unbounded evidence, or an MCP authority increase are especially important.

The harness does not make contributed commands intrinsically safe. Catalog review and device-side read-only AAA remain required defenses.
